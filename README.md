# Automated Supply Chain Reporting Pipeline

A Python script that consolidates multiple raw Excel/CSV planner exports — each
from a different regional team, each with its own formatting quirks — into a
single cleaned dataset, then auto-generates a summary pivot report. Built to
remove the manual weekly data-wrangling an analyst would otherwise do by hand.

**Tools:** Python, pandas, openpyxl

---

## The problem this solves

Every week, five regional teams each export their own planner file. None of
them look the same:

| File | Format quirk |
|---|---|
| `planner_export_north_week32.xlsx` | Clean — this is what a "correct" export looks like |
| `planner_export_south_week32.csv` | Messy header names (`" SKU "`, `"region "`, `"Units_Sold"`) and US-style `MM/DD/YYYY` dates |
| `planner_export_east_week32.csv` | Two metadata rows above the real header row, plus one accidental duplicate row |
| `planner_export_west_week32.xlsx` | Missing `Units Sold` values on some rows, one fully blank row, dates stored as text |
| `planner_export_central_week32.csv` | Columns in a different order, inconsistent Region casing (`"central"` vs `"Central"`), one negative-units data-entry error |

Manually opening all five, fixing headers, retyping dates, and copy-pasting
into one master sheet is exactly the kind of repetitive weekly task this
pipeline eliminates.

## What the pipeline does

1. **Reads every file** in `data/raw_exports/`, regardless of `.csv` or `.xlsx`
2. **Detects and skips metadata rows** above the real header (East's export)
3. **Normalizes column names** — strips whitespace, fixes casing, maps
   `Units_Sold` / `units sold` / `Units Sold` all onto one canonical name
4. **Parses dates in mixed formats** — `MM/DD/YYYY` text, `YYYY-MM-DD` text,
   and real Excel date objects all get parsed correctly in the same pass
5. **Standardizes categorical values** — `"central"` and `"Central"` become
   the same value
6. **Cleans the data**, logging exactly what it removed and why:
   - drops fully blank rows
   - drops rows with an unparseable date
   - drops rows with missing `Units Sold` (excluded rather than guessed at)
   - drops rows with a negative `Units Sold` (data-entry error)
   - drops exact duplicate rows
7. **Tags every row with its source file**, so any number can be traced
   back to the exact export it came from
8. **Writes a consolidated CSV** — one clean dataset, one row per
   SKU/Region/Date
9. **Auto-generates a multi-sheet Excel summary report**:
   - `Pivot - SKU x Region` — total units sold, SKU × Region
   - `Pivot - Weekly Trend` — total units sold, SKU × Week
   - `Consolidated Data` — the full cleaned dataset
   - `Data Quality Log` — exactly what the pipeline did on this run

## How to run it

```bash
pip install -r requirements.txt

# (optional) regenerate a fresh batch of sample raw files
python generate_raw_data.py

# run the pipeline
python pipeline.py
```

Every run prints (and saves to `output/pipeline_log.txt`) a summary like:

```
Combined raw rows from all files: 562
Cleaning consolidated dataset...
  Dropped 1 row(s) with an unparseable date
  Dropped 5 row(s) with missing Units Sold (demand can't be safely assumed, so these are excluded rather than filled)
  Dropped 1 row(s) with a negative Units Sold value (data-entry error)
  Dropped 1 exact duplicate row(s)
  Result: 562 raw rows -> 554 clean rows
```

## Design decisions worth knowing (for talking through in an interview)

- **Missing `Units Sold` is dropped, not filled with 0 or an average.**
  Silently inventing a sales number would corrupt any downstream demand
  analysis. Excluding it and logging it keeps the dataset honest and gives
  a data-quality signal back to whoever owns that source file.
- **`pd.to_datetime(..., format="mixed")`** — once files with different date
  formats are concatenated into one column, pandas' default behavior infers
  a single format from the first value in the column and silently returns
  `NaT` for every row that doesn't match it. `format="mixed"` parses each
  value independently instead, which is required here since South uses
  `MM/DD/YYYY` while the others use `YYYY-MM-DD`.
- **Every row keeps a `Source File` column** for traceability — if a number
  in the final report looks wrong, you can trace it back to the exact
  regional export it came from, without re-running anything.
- **Running weekly**: drop next week's five files into `data/raw_exports/`
  (any filenames, the script doesn't care) and rerun `pipeline.py`. On
  Windows this can be scheduled with Task Scheduler; on macOS/Linux with
  `cron`.
